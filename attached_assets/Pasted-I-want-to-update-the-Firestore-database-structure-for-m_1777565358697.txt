I want to update the Firestore database structure for my Smart Study Planner app.

Database location: nam5

The `users` collection should be the main place where user membership/role information is stored.

Please remove all app dependency on these collections:
- memberships
- userIndex
- invitations

The app should no longer create, read, update, or query those collections anywhere.

After the code is updated, I will manually delete those collections from Firebase Console, but the app code must stop using them first.

New Firestore structure:

1. users/{uid}

Each user document must contain:

{
  createdAt: serverTimestamp(),
  displayName: authUser.displayName || null,
  email: authUser.email,
  organizationId: string | null,
  organizations: [
    {
      organizationId: string,
      role: "admin" | "teacher" | "student",
      status: "activated"
    }
  ],
  uid: authUser.uid,
  updatedAt: serverTimestamp()
}

Important:
- `users` is the main collection for user profile + organization access.
- Keep the top-level `organizationId` field.
- `organizationId` should represent the user’s current/default organization.
- The `organizations` array stores every organization the user belongs to.
- Each object inside `organizations` must contain:
  - organizationId
  - role
  - status

Example user document:

{
  createdAt: Timestamp,
  displayName: null,
  email: "sarinakavoli@icloud.com",
  organizationId: "org_waterloou",
  organizations: [
    {
      organizationId: "1234",
      role: "admin",
      status: "activated"
    },
    {
      organizationId: "456",
      role: "student",
      status: "activated"
    }
  ],
  uid: "AvU4OpeL5WO79GRp67C6JiJUYUY2",
  updatedAt: Timestamp
}

Please use the spelling `organizationId`, not `organizatoinId`.

2. organizations/{organizationId}

The organizations collection should only contain information about the organization itself.

Example organization document:

{
  createdAt: serverTimestamp(),
  createdBy: authUser.uid,
  createdByEmail: authUser.email,
  id: "org_uot"
}

Do not store user membership data inside the organization document unless it is only basic organization metadata.

  - displayName

status === "activated"
